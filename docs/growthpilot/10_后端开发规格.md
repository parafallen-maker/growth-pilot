# 10 后端开发规格

## 1. 推荐栈

- NestJS 11
- TypeScript
- PostgreSQL 16
- Prisma 或 Drizzle
- Redis
- BullMQ
- S3 兼容存储

## 2. 模块划分

```text
src/modules/
  auth/
  users/
  settings/
  teachers/
  students/
  families/
  homework/
  growth/
  attendance/
  billing/
  communication/
  analytics/
  jobs/
  files/
```

## 3. 每个模块内部建议结构

```text
module/
  controller/
  service/
  repository/
  dto/
  entity/
  mapper/
  policy/
  event/
  job/
```

## 4. 分层职责

### Controller
- 接收 HTTP 请求
- DTO 校验
- 返回 Response VO

### Service
- 实现用例
- 编排事务
- 发布领域事件

### Repository
- 封装 ORM 查询
- 不做业务流程判断

### Policy
- 权限、数据域判断

### Job
- 异步任务处理器

## 6. 事务边界

以下操作必须使用事务：

1. 创建学生 + 创建家庭 + 创建在读档
2. 创建合同 + 合同明细
3. 创建账单 + 账单明细
4. 记录支付 + 更新账单状态
5. 记录退款 + 更新支付/账单衍生状态
6. 提交作业复核 + 写入错因明细 + 更新 submission 状态
7. 生成报告草稿 + 写入 report + 写入消息草稿

## 7. 领域事件

推荐使用应用内事件总线即可。

| 事件 | 生产者 | 消费者 |
|---|---|---|
| StudentCreated | students | analytics, operation_logs |
| EnrollmentCreated | students | teachers, analytics |
| HomeworkSubmitted | homework | jobs |
| HomeworkAnalyzed | jobs | homework |
| HomeworkReviewed | homework | growth, communication, analytics |
| GrowthObservationCreated | growth | growth, analytics |
| GrowthReportPublished | growth | communication |
| InvoiceIssued | billing | communication, analytics |
| PaymentSucceeded | billing | analytics |
| AttendanceCaptured | attendance | analytics |

## 8. AI 适配器接口

后端不要把模型厂商写死在业务模块里，统一走 adapter。

```ts
export interface HomeworkAnalysisAdapter {
  analyze(input: {
    submissionId: string;
    subject: string;
    gradeLabel?: string;
    imageUrls: string[];
    promptVersion: string;
  }): Promise<{
    rawMarkdown: string;
    structured: {
      accuracyPct: number;
      errorItems: Array<{
        code?: string;
        label: string;
        evidence?: string;
      }>;
      summary: string;
      suggestion: string;
      confidence?: number;
    };
  }>;
}
```

## 9. DTO 规范

### Create DTO
只用于创建

### Update DTO
全部可选，但不可把不可改字段暴露出来

### Query DTO
统一继承分页筛选基类

```ts
class BasePageQueryDto {
  pageNo?: number;
  pageSize?: number;
  keyword?: string;
  campusId?: string;
  termId?: string;
  status?: string;
}
```

## 10. 幂等设计

### 支付
- `payment_no` 唯一
- 同时支持 `Idempotency-Key`

### 退款
- `refund_no` 唯一

### 签到
- 设备事件采用 `(device_id, event_time, event_type)` 去重

### AI 任务
- 同一 submission 在 `pending/running` 状态下禁止重复建同类型 job

## 11. 导入策略

历史 Excel 导入不能直接写正式表，建议两段式：

1. `staging_*` 临时表或 JSON 临时落库
2. 清洗、去重、映射后写正式表

导入顺序：
1. campuses / terms / users / teachers
2. families / guardians / students
3. enrollments / external courses / tags
4. devices / bindings
5. homework submissions / analyses / reviews
6. growth observations
7. billing contracts / invoices / payments

## 12. 聚合查询建议

### Student 360
单独提供聚合接口，不让前端多接口拼装。

返回建议：
```json
{
  "student": {},
  "currentEnrollment": {},
  "family": {},
  "homeworkSummary": {},
  "growthSummary": {},
  "attendanceSummary": {},
  "billingSummary": {},
  "recentTimeline": []
}
```

### Analytics
- 预聚合到 `kpi_daily_snapshots`
- 重型趋势图允许定时任务离线算

## 13. 权限与数据域

### 权限
基于 `permission code`

### 数据域
基于：
- campus
- teacher ownership
- module action

示例：
- subject_teacher 只能看自己当前在带学生的数据
- finance 不能改成长观察
- receptionist 不能看收费金额

## 14. 日志要求

### operation_logs
记录：
- user_id
- module
- action
- biz_type
- biz_id
- before_json（可选）
- after_json（可选）
- trace_id

### AI 日志
保留：
- provider
- model_name
- model_version
- prompt_version
- duration_ms
- input/output token（如果有）

## 15. 定时任务建议

- 每日生成 KPI 快照
- 每晚聚合作业时长日统计
- 每周生成周报草稿任务
- 每月生成账龄快照
- 续费到期提醒扫描

## 17. 大模型编码约束

1. 先生成模块 skeleton
2. 再生成 DTO / entity / repository
3. 再生成 controller / service
4. 最后补 tests
5. 不要在 controller 里写 ORM
6. 不要把聚合 SQL 塞满 service，复杂聚合单独 query repository
