# 17 联调与验收清单

> 用途：给 QA、PM、负责人做统一联调、验收、上线前检查。
> 原则：不凭感觉验收，只按文档、接口、数据、主流程、缺陷等级逐项过。

---

## 1. 适用范围

本清单覆盖以下交付范围：
- 组织与权限
- 学生 / 家庭 / 教师主数据
- 作业上传 / AI 分析 / 教师复核
- 成长观察 / 目标 / 报告
- 出勤 / 设备 / 作业时长
- 产品 / 合同 / 账单 / 支付 / 退款 / 续费
- 沟通记录 / 消息中心
- Analytics 看板
- 历史数据导入
- 预发上线与回滚

---

## 2. 验收角色分工

| 角色 | 核心职责 | 关注重点 |
|---|---|---|
| QA | 执行测试、回归、缺陷归档 | 功能正确性、异常分支、边界条件 |
| PM / Product | 对照 PRD 与页面原型验收 | 是否满足业务目标、是否跑通流程 |
| 负责人 | 最终业务签收 | 是否达到可上线与可经营使用标准 |
| Backend Owner | 接口、事务、数据一致性确认 | 事务、幂等、日志、性能 |
| Frontend Owner | 页面、交互、权限态确认 | 状态完整性、表单、列表、工作台 |
| Migration / BI Owner | 导入、指标、口径确认 | 数据准确性、历史可追溯 |

### 性能目标
- [ ] 常规列表页 P95 < 800ms
- [ ] 详情页 P95 < 1200ms
- [ ] overview 看板 P95 < 3000ms

### 稳定性目标

- [ ] 日志可追踪到 traceId

---

## 8. 缺陷等级与放行规则

### 缺陷等级
- **P0**：主流程断裂、数据错乱、权限失控、支付错误、无法上线
- **P1**：核心功能可绕过但不可接受、明显错误、影响大面积用户
- **P2**：局部交互、样式、提示、边界问题
- **P3**：优化项、体验项、非阻塞建议

### 放行规则
- [ ] P0 = 0
- [ ] P1 = 0
- [ ] P2 已登记并有明确修复计划
- [ ] P3 不阻塞上线

## 10. 验收输出物

每轮联调或验收结束，至少输出这些东西：

1. 测试报告
2. 缺陷清单
3. 回归结果
4. 指标口径确认单（如果涉及 analytics）
5. 导入校验报告（如果涉及 migration）
6. 是否准许进入下一 wave / 是否准许上线 的结论

## 12. 最终判断标准

一句话：

**不是“页面看起来差不多”就算验收，而是“文档一致、数据可信、流程闭环、异常可控、上线可回滚”才算验收。**
