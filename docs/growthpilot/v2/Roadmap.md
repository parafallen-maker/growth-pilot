# GrowthPilot v2 — 十版本路线图 (10-Version Roadmap)

> 作者：鸽鸽 | 日期：2026-04-05 | 状态：Draft
> 关联文档：PRD.md, SPEC.md

---

## 版本规划总览

```
V1  基座加固          ← 修现有问题，打基础
V2  今日工作台        ← 教师体验质变
V3  孩子成长档案      ← 核心信息重构
V4  关联分析引擎      ← 智能化增强（非首要闭环）
V5  周报引擎          ← 系统最重要的产出
V6  成长计划系统Lite  ← 从记录过渡到轻量干预
V7  运营层重构        ← 收费+考勤体验升级
V8  数据迁移+Excel    ← 历史数据接入与试运行验证
V9  上线就绪          ← 生产化+监控+文档
V10 管理概览增强      ← 校长视图 / 经营分析增强
```

> 路线调整原则：**先交付教师闭环，再补智能化和经营层增强。**

## V2 — 今日工作台（3天）

**目标：教师打开系统，在常规工作日 15 分钟内知道今天最该做什么**

### 任务

| # | 任务 | 说明 |
|---|------|------|
| 1 | 后端：`GET /api/v1/today` 聚合 API | 返回 must_do + weekly_due + escalations + completed_today |
| 2 | 后端：观察提示生成服务 | 每日定时扫描，按规则生成待观察提示 |
| 3 | 后端：`GET /api/v1/observation-prompts` | 教师获取今日提示列表 |
| 4 | 前端：Today 页面 | 今天必须处理 + 本周应完成 + 风险升级 + 已完成区域 |
| 5 | 前端：从 Today 直达复核 | 点击卡片 → 跳转复核页面 |
| 6 | 前端：从 Today 直达观察 | 点击卡片 → 跳转观察记录 |
| 7 | 前端：提示完成/忽略 | 操作后 Today 实时更新 |

### 设计稿

```
┌─ Today ──────────────────────────────────┐
│ 👋 早上好，张老师                          │
│                                           │
│ 📋 今天必须处理 (3)        [查看全部 →]    │
│ ┌─ 小明 · 数学 · 正确率78% ────────────┐  │
│ │ AI建议：关注进位加法           [去复核]│  │
│ └──────────────────────────────────────┘  │
│                                           │
│ 👁️ 本周应完成 (2)          [查看全部 →]    │
│ ┌─ 小刚：习惯评分骤降3天 ──────────────┐  │
│ │ 建议观察：专注力、情绪状态       [记录]│  │
│ └──────────────────────────────────────┘  │
│                                           │
│ ⚠️ 风险升级 (1)            [查看全部 →]    │
│ └─ 小明：数学连续3天正确率<70%      [处理]│
│                                           │
│ ✅ 今日已完成 (5)                         │
│ └─ 复核 3 份作业 · 记录 2 次观察          │
└───────────────────────────────────────────┘
```

### 验收标准
- 教师登录后默认进入 Today
- 首页只展示 3 个优先队列，每队列默认前 5 项
- 每个卡片可点击直达操作
- 操作完成后卡片消失，已完计数 +1

## V3 — 孩子成长档案（5-7天）

**目标：从“学生数据表”变成“成长故事”**

### 任务

| # | 任务 | 说明 |
|---|------|------|
| 1 | 后端：`GET /api/v1/children/:id/profile` 聚合 API | 学业+习惯+考勤+家庭+计划+信号 |
| 2 | 后端：`GET /api/v1/children/:id/timeline` 时间线 API | 跨模块事件按时间排列 |
| 3 | 数据库：`growth_plans` 表 | 先做 Lite 版本持久化 |
| 4 | 后端：成长计划 CRUD Lite | 目标 + 备注 + 进度 |
| 5 | 前端：孩子成长档案页面 | 第一屏判断、第二屏趋势、第三屏明细 |
| 6 | 前端：成长脉络组件 | 学业趋势 + 习惯趋势 + 考勤趋势 |
| 7 | 前端：时间线组件 | 作业/观察/沟通/收费事件按时间展示 |
| 8 | 前端：成长计划 Tab（Lite） | 目标 + 备注 + 进度 |
| 9 | 前端：关联信号展示区 | V4 前先占位，V4 后接真实数据 |
| 10 | 数据库：`students.growth_snapshot` | 成长快照缓存 |

### 信息架构

```
孩子 → 小明
├─ 第一屏：变化 / 风险 / 下一步
├─ 第二屏：趋势与计划
├─ 第三屏：作业 / 观察 / 家庭 / 收费明细
└─ 时间线：按日期展示关键事件
```

### 验收标准
- `/children/:id` 页面加载完整数据
- 第一屏能直接回答“本周最重要的三件事”
- 时间线至少展示作业+观察两类事件
- 成长计划 Lite 可创建、更新进度

## V4 — 关联分析引擎（3天）

**目标：系统开始“看见”维度间的关联，但不抢教师闭环优先级**

### 任务

| # | 任务 | 说明 |
|---|------|------|
| 1 | 数据库：`analysis_signals` 表 | 存储分析信号 |
| 2 | 后端：规则引擎 Lite | 首批只支持少量高价值规则 |
| 3 | 后端：核心规则实现 | 学业-习惯关联、学习时长骤降、连续低表现 |
| 4 | 后端：`POST /api/v1/analysis/refresh/:studentId` | 手动触发分析刷新 |
| 5 | 后端：定时任务（每日 03:00） | 批量刷新所有活跃学生分析 |
| 6 | 前端：信号卡片组件 | 在孩子档案页展示分析发现 |
| 7 | 前端：信号确认/忽略 | 教师反馈信号是否有效 |

### 核心规则（首批 3 条）

| 规则ID | 触发条件 | 严重度 | 建议 |
|--------|---------|--------|------|
| academic_habit_correlation | 学业↓ + 习惯↓ 同步发生 | concern | 先了解情绪和家庭因素 |
| engagement_drop | 学习时长骤降 > 40% | watch | 确认是否有外因 |
| streak_low_performance | 连续3次作业正确率 < 70% | concern | 安排专项辅导 |

### 验收标准
- 手动刷新可返回信号列表
- 孩子档案页展示关联信号卡片
- 教师可确认/忽略信号

## V5 — 周报引擎（5-7天）

**目标：系统最重要的产出——每周自动为每个孩子生成成长反馈**

### 任务

| # | 任务 | 说明 |
|---|------|------|
| 1 | 数据库：`weekly_digests` 表 | 周报持久化 |
| 2 | 后端：周报生成器 | 汇总作业+习惯+考勤+信号+计划 |
| 3 | 后端：家庭建议生成 | 基于已有结构化证据生成 |
| 4 | 后端：`POST /api/v1/weekly-digest/generate` | 批量生成本周草稿 |
| 5 | 后端：`GET /api/v1/weekly-digest/current` | 当前周报列表 |
| 6 | 后端：`PATCH /api/v1/weekly-digest/:id` | 教师审阅修改 |
| 7 | 后端：周报状态机 | 可直接发送 / 数据不足需补充 / 暂不建议发送需主管确认 |
| 8 | 后端：定时任务（每周一 00:00） | 自动生成草稿 |
| 9 | 前端：周报列表页 | 本周所有学生的周报状态 |
| 10 | 前端：周报编辑页 | 左侧自动摘要 + 右侧教师评语编辑 |
| 11 | 前端：周报预览组件 | 手机端预览效果 |
| 12 | 前端：批量操作 | 批量批准、批量发送 |

### 验收标准
- 定时任务每周一生成草稿
- 周报支持 3 种状态：可直接发送 / 数据不足需教师补充 / 暂不建议发送需主管确认
- 教师评语为必填项
- 预览模式展示最终样式

**总工期：约 8 周可交付试运行闭环版；若要稳定替换 v1，建议预留 10–12 周。**

## 风险与依赖

| 风险 | 影响 | 缓解 |
|------|------|------|
| Tailwind 迁移内联样式工作量大 | V1 延期 | 分批迁移，新页面强制 Tailwind |
| 关联分析规则不准确 | V4 价值打折 | 首批只上 3 条高价值规则，教师反馈迭代 |
| 周报自动生成质量不够 | V5 不可用 | 草稿 + 教师修改 + 数据不足状态兜底 |
| 教师采纳风险 | Today 第二天不再打开 | 首页只保留 3 个优先队列，用试点班级验证 |
| 数据稀疏风险 | 周报质量不稳定 | 先做数据不足状态，并通过导入 / 补录提高覆盖 |
| 组织流程风险 | 校长不把成长反馈纳入日常管理 | 试运行版同步最小管理指标与周例会机制 |
| 4 人团队并行能力有限 | 整体延期 | Phase A 聚焦 Today → Children → Weekly 闭环 |
| 历史数据质量差 | V8 阻塞 | 提前做数据审计，制定清洗规则 |
