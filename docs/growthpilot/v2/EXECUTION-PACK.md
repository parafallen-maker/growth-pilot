# GrowthPilot v2 — Phase A Execution Pack

> 状态：For Execution  
> 基于文档：PRD.md / Roadmap.md / PM-REVIEW-SUMMARY.md  
> 目标：把 v2 收敛成一份可直接开工的试运行闭环交付包

---

## 1. Phase A 唯一目标

**在 1 个试点班级跑通教师闭环：教师能基于真实或可迁移历史数据，完成 Today → Children → Weekly 的最小工作流，并产出可审阅、可发送的周报。**

这意味着本阶段不是做“完整新系统”，而是验证下面这件事是否成立：

> 系统能否在不显著增加教师负担的前提下，把分散数据收敛成每周可交付的成长反馈。

---

## 2. Phase A 范围边界

### 2.1 范围内

仅包含以下 5 个版本收敛后的最小闭环：
- **V1** 基座加固
- **V2** Today 工作台
- **V3** 孩子成长档案
- **V5** 周报引擎
- **V8** 数据迁移试运行

### 2.2 明确保留但不纳入 Phase A 交付

以下内容不阻塞闭环验证，全部后置：
- V4 关联分析引擎正式版
- V6 成长计划系统深化版
- V7 运营层重构
- V9 生产级上线就绪
- V10 管理概览增强
- 家长端 App
- 排课系统
- 复杂多校区权限
- BI 大屏 / 校长大屏
- AI 自动决策类能力

### 2.3 Phase A 内的降级原则

为保证闭环优先，允许以下降级：
- **成长计划仅保留 Lite 占位**：如当前开发资源不足，可仅在孩子档案中展示“当前目标/备注/进度”的静态或轻量可编辑区，不扩展动作编排。
- **关联分析不做正式规则引擎**：Phase A 只消费已有结构化数据，不以 V4 为前置依赖。
- **周报发送先做到“可审阅、可导出/可复制发送”**：若真实外发链路未定，可先不接正式消息渠道。

---

## 3. Phase A 成功标准

只有同时满足以下条件，Phase A 才算完成：

### 3.1 闭环可跑通
- 试点班级至少 1 个
- 可通过迁移或补录拿到可用学生数据
- 教师可每日进入 Today 查看待处理项
- 教师可进入孩子档案查看本周变化/风险/下一步
- 系统可生成周报草稿，教师可审阅并形成最终版本

### 3.2 数据可支撑周报
- 至少可汇总以下证据源中的核心字段：
  - 作业
  - 观察
  - 基础学生信息
  - 必要的班级/教师归属
- 数据不足的学生，周报状态能明确标记为“需补充”，而不是静默失败

### 3.3 教师侧体验可接受
- 教师登录默认进入 Today
- Today 首页只保留 3 个优先队列，且每队列默认最多 5 项
- Today 卡片可直达处理动作
- 完成操作后状态有反馈，Today 数据同步更新

### 3.4 试运行可验证
- 至少 1 个试点班级完成一次完整周报生成与审阅流程
- 重复导入历史数据不会产生重复记录
- 导入错误能给出明确行级提示

---

## 4. Phase A 非目标

本阶段**不承诺**以下结果：
- 全量替换 v1
- 面向所有角色的一次性完整重构
- 复杂智能分析的准确性验证
- 经营管理视图完备
- 生产级监控、备份、回滚全部齐备

Phase A 的判断标准是“试运行闭环成立”，不是“全面上线完成”。

---

## 5. 交付结构

Phase A 交付拆成 5 个工作包，按先后顺序执行：

1. **WP1 基座就绪（V1）**
2. **WP2 Today 工作台（V2）**
3. **WP3 孩子成长档案（V3）**
4. **WP4 周报引擎（V5）**
5. **WP5 数据迁移与试运行（V8）**

原则：**先把系统跑稳，再把教师入口做顺，再把信息收敛成档案，再把输出做成周报，最后用真实数据验证。**

## 9. 必须先确认的开放问题（仅保留真正阻塞开发的）

以下问题若不确认，会直接阻塞 Phase A：

### O1. 试点班级与数据来源是谁？
- **为什么阻塞**：不确认试点对象，V8 无法设计导入映射，V5 无法定义周报样本口径。
- **需要拍板内容**：
  - 试点班级数量
  - 是否有历史 Excel
  - 数据拥有者是谁

### O2. 学生唯一标识规则是什么？
- **为什么阻塞**：没有稳定唯一键，历史数据导入无法幂等，Today/档案/周报会出现重复或串档。
- **需要拍板内容**：
  - 使用 student_no / 手机号 / 姓名+班级 / 其他编号中的哪一个
  - 历史数据缺失时的补齐策略

### O3. 周报最终“发送”在 Phase A 的定义是什么？
- **为什么阻塞**：周报交付标准依赖“发送”定义；若不明确，验收口径会漂移。
- **需要拍板内容**：
  - Phase A 只要求“可审阅并导出/复制发送”
  - 还是必须接入真实消息渠道

### O4. Phase A 是否必须包含成长计划 Lite 的可编辑能力？
- **为什么阻塞**：V3 当前把 growth plan Lite 夹带进来，但其深度会影响接口和页面范围。
- **需要拍板内容**：
  - 仅展示占位
  - 轻量可编辑
  - 完全后置到 Phase B

## 10. 当前文档中的冲突与收敛结论

### 冲突 1：PRD 的 MVP 范围 vs PM 审阅建议的闭环优先
- **PRD 写法**：MVP 包含 Today、Children、Weekly、收费闭环、机构设置、成长计划 Lite 等较多能力。
- **PM 审阅结论**：必须先收窄到 Today → Children → Weekly，避免范围失控。
- **本执行包结论**：
  - **Phase A 只对教师闭环负责**。
  - 收费闭环、机构设置仅保留必要支撑，不单列为本阶段核心交付。

### 冲突 2：Roadmap 把 V8 作为第 8 个版本，但时间线上又要求第 5 周试运行
- **问题本质**：容易让团队误以为“迁移是最后做”，实际迁移准备应前置。
- **本执行包结论**：
  - **V8 的数据定义和映射策略从 Week 1 就要启动**。
  - 试运行验证放在后段执行，但数据准备不能后置。

### 冲突 3：V3 包含 growth plan Lite，但 PM 审阅强调先交付闭环
- **问题本质**：成长计划容易自然膨胀成独立子系统。
- **本执行包结论**：
  - Growth plan Lite 不是 Phase A 核心目标。
  - 如保留，只能是轻量字段，不得扩展成复杂流程。

### 冲突 4：PRD 提到周报“自动推送”，但当前文档未明确外发链路
- **问题本质**：若把“推送”当成必须，会把交付链路和第三方通道接入绑死。
- **本执行包结论**：
  - Phase A 以“生成可审阅、可确认、可交付的周报版本”为验收口径。
  - 真实消息渠道接入不是本阶段必备项，除非业务明确要求。

## 12. Phase A 完成定义（DoD）

Phase A 结束前，必须看到以下证据：
- 有一套可用的 Today 页面
- 有一套可用的孩子成长档案页面
- 有一套可用的周报生成与审阅流程
- 有一次真实或准真实数据迁移试跑结果
- 有至少 1 个试点班级完成闭环验证记录
- 有一份试运行问题清单，并区分阻塞项与优化项

---

## 13. 最终执行结论

**Phase A 不做“大而全重构”，只做一件事：验证教师闭环是否成立。**

因此执行优先级固定为：

**V1 基座 → V2 Today → V3 Children → V5 Weekly → V8 数据迁移试运行**

任何不直接服务这条链路的需求，都不应在 Phase A 插队。
