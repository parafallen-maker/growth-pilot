# GrowthPilot v2 — 第一性原理产品重设计

> 作者：鸽鸽 | 日期：2026-04-05 | 状态：Draft

---

## 0. 为什么要重设计？

**当前 v1 的核心问题：产品是"机构管理系统顺带记录成长"，而不是"成长支持系统顺带管运营"。**

证据：

| 维度 | v1 现状 | 问题 |
|------|---------|------|
| 信息架构 | 按**管理域**组织（学生/教师/家庭/收费/考勤/沟通…13个模块） | 没有人按这个思路工作 |
| 核心循环 | 数据录入 → 列表展示 → 预警通知 | 录完就结束，没有闭环 |
| 成长模块 | 埋在 Growth 子菜单里，和作业/考勤/收费平级 | 成长应该是主线，不是其中一个模块 |
| 教师体验 | 打开系统看到 13 个菜单入口 | 教师每天的工作只有 3 件事：看作业、记观察、跟家长说两句 |
| 数据关系 | 作业分析和习惯观察各存各的 | 一个孩子今天作业全对但情绪低落——系统看不到关联 |
| 价值交付 | 周报是最后一个环节，手工触发 | 周报应该是系统最自然的产出 |

---

## 1. 第一性原理推导

### 1.1 终极问题

**"什么系统能让每个孩子获得持续、个性化、有据可循的成长支持？"**

拆解：

1. **持续** → 每天都有观察记录，不是每周一次性补
2. **个性化** → 系统知道每个孩子的模式，不是统一模板
3. **有据可循** → 所有判断有数据支撑，不是靠印象

### 1.2 核心约束

- 机构 4 人团队，不能增加操作负担
- 教师每天用在系统上的时间不能超过 15 分钟
- 家长端暂不做 App，但必须有可传递的信息载体
- 数据必须可迁移（Excel 历史）

### 1.3 推导出的产品核心循环

```
观察（Observe）→ 理解（Understand）→ 行动（Act）→ 追踪（Track）
```

这不是 CRUD，这是一个**持续运转的支持引擎**。

## 2. 产品重新定义

### 2.1 一句话定义

**GrowthPilot 是面向课后教育机构的「儿童成长支持系统」——以每日观察和作业分析为输入，以个性化成长计划为输出，以家校协同为放大器。**

### 2.2 产品北极星指标

**北极星指标：每周成长反馈有效覆盖率**

定义：
- **覆盖**：学生当周收到 1 条成长反馈
- **有据**：反馈中至少引用 1 个结构化证据源（作业 / 习惯 / 时长 / 分析信号）
- **有效**：教师完成审阅确认后发出

配套指标：
- 覆盖率 = 已收到有效反馈学生数 / 在读学生数
- 审阅率 = 已审阅反馈数 / 自动生成草稿数
- 按时率 = 周四前完成发送的反馈数 / 应发送反馈数

不是"系统里有多少条数据"，而是"孩子和家长实际收到了多少有价值、经教师确认的反馈"。

### 2.3 四条产品红线

1. **成长是主线，运营是基座** — 菜单和流程围绕孩子成长组织，运营（收费/考勤）是支撑层
2. **教师 15 分钟法则** — 日常情况下 80% 教师日操作 ≤ 15 分钟；高峰日 ≤ 25 分钟
3. **数据不动内容动** — 一次录入，多次复用（作业分析 → 错因 → 观察 → 周报 → 家长沟通）
4. **输出优先于分析炫技** — 任何分析、提示、计划功能，都必须最终提升“成长反馈交付效率或质量”，否则不进入 MVP

## 3. 信息架构重设计

### v1 架构（管理视角）
```
Dashboard → Students → Families → Teachers → Homework → Growth → Billing → ...
```

### v2 架构（成长视角）

```
┌─────────────────────────────────────────────┐
│  今日视图 (Today)                            │  ← 教师每天打开的第一个页面
│  我的待复核作业 | 今日观察待记 | 待跟进预警   │
├─────────────────────────────────────────────┤
│  孩子们 (Children)                           │  ← 每个孩子的成长全景
│  ┌─ 成长档案（不是学生档案）                  │
│  │  学业表现 + 习惯模式 + 情绪信号 + 家庭背景  │
│  │  → 自动生成的成长脉络，不是数据表格         │
│  └─ 成长计划（不是任务列表）                  │
│     当前目标 + 干预措施 + 下一步动作           │
├─────────────────────────────────────────────┤
│  周报引擎 (Weekly Digest)                    │  ← 系统最重要的产出
│  自动生成草稿 → 教师审阅修改 → 家长收到       │
├─────────────────────────────────────────────┤
│  运营 (Operations)                           │  ← 支撑层，不抢主线
│  收费 | 考勤 | 设备 | 通讯 | 设置             │
└─────────────────────────────────────────────┘
```

### 关键变化

| v1 | v2 | 为什么 |
|----|-----|--------|
| 13 个一级菜单 | 教师主导航 4 个区域 | 教师不需要看到"收费" |
| Dashboard 是统计图表 | Today 是待办工作台 | 打开系统就知道今天做什么 |
| Student 360 是数据汇总 | 孩子档案是成长故事 | 从"表"变成"人" |
| Growth 是一个模块 | 成长是贯穿所有模块的主线 | 作业、考勤、观察都为成长服务 |
| 周报手工触发 | 周报是系统自动产出 | 减少教师工作量，保证交付 |

> 补充说明：**4 区域是教师主导航，不等于管理层只有 4 个入口。** 管理层保留独立经营总览 / 经营视图入口，避免经营数据被藏深。

## 4. 核心功能设计

### 4.1 今日视图 (Today)

**教师每天打开的第一个页面，目标是在常规工作日 15 分钟内完成当天最关键的工作。**

```
今日视图
├── 📋 今天必须处理（最多 5 项）   ← 今日到期、不处理会阻塞交付
│   └─ 小明 · 数学 · 正确率78% · 建议关注"进位加法"
├── 👁️ 本周应完成（最多 5 项）    ← 观察、沟通、补录等本周任务
│   └─ 小红 · 连续3天作业正确率下降 · 建议观察情绪
├── ⚠️ 风险升级（最多 5 项）      ← 超期未跟进或等级升级的风险
│   └─ 小刚 · 欠费15天 · 需联系家长
└── ✅ 今日已完成                ← 已完成的操作，给教师成就感
```

**设计原则：**
- 打开就知道做什么
- 首页只保留 3 个优先队列，每队列默认前 5 项，避免待办堆积击穿 Today
- 操作路径 ≤ 2 步
- AI 做了草稿，教师只做确认和补充

### 4.2 孩子们 (Children)

**每个孩子一个"成长档案"，不是"学生数据表"。档案必须遵守“先给判断，再给证据，最后给明细”的信息分层。**

```
成长档案
├── 第一屏：本周最重要的 3 件事       ← 变化 / 风险 / 下一步
│   ├─ 变化：数学应用题正确率连续 2 周上升
│   ├─ 风险：专注力评分较上周下降 1.2 分
│   └─ 下一步：本周完成 3 次审题专项练习
│
├── 第二屏：趋势与计划               ← 跨维度趋势图 + 当前目标
│   ├─ 学业趋势：正确率 + 错因分布 + 掌握进度
│   ├─ 习惯模式：各维度评分变化 + 关联分析
│   └─ 当前目标：自主完成数学应用题（进度60%）
│
├── 第三屏：原始记录与时间线          ← 明细作为证据层
│   ├─ 每次作业：图片 + AI分析 + 教师评语 + 错因标签
│   ├─ 家庭沟通：最近联系记录与建议
│   └─ 收费状态（折叠）              ← 不在第一屏，但可查
```

**与 v1 的核心区别：**
- v1 的 Student 360 是"把所有数据摆在同一个页面"
- v2 的成长档案是"按成长逻辑组织信息，并自动发现关联"

### 4.3 周报引擎 (Weekly Digest)

**这是系统最有价值的产出，不是最后一个步骤。**

```
周报引擎工作流：

周一 00:00  系统自动生成草稿
            ├─ 本周作业表现摘要（自动统计）
            ├─ 习惯观察趋势（自动汇总）
            ├─ 异常信号提醒（系统检测）
            ├─ 家庭配合建议（基于模式生成）
            └─ 教师评语区（待教师填写）

周一-周三    教师审阅修改
            ├─ 确认数据无误
            ├─ 补充个人观察
            └─ 调整家庭建议措辞

            审阅结果分为 3 种状态：
            ├─ 可直接发送
            ├─ 数据不足，需教师补充
            └─ 暂不建议发送，需主管确认

周四         自动推送
            ├─ 生成可分享格式（图片/链接）
            └─ 教师确认后发送给家长
```

**v1 vs v2：**
- v1：周报是 Growth 模块下的一个按钮
- v2：周报是系统核心产出，所有数据都为周报服务

### 4.4 运营层 (Operations)

**折叠到二级，按角色可见。**

| 子模块 | 说明 | 谁需要 |
|--------|------|--------|
| 收费中心 | 合同、账单、收款、退费、续费 | 财务 |
| 考勤设备 | 签到、设备绑定、学习时长 | 教务 |
| 通讯记录 | 家长沟通历史、模板消息 | 全员 |
| 机构设置 | 校区、学期、字典、用户权限 | 管理员 |

## 5. 关键创新点

### 5.1 跨维度关联分析

**v1 的致命盲区：作业和习惯是两个独立模块。**

v2 的核心算法：
```
IF 孩子本周作业正确率下降 > 15%
   AND 专注力评分下降 > 1分
   AND 无缺课记录
THEN 标记"学业-习惯关联预警"
     建议：先排除情绪/家庭因素
```

### 5.2 智能观察提示

**不是让教师"记得"去观察，而是系统告诉教师"今天该观察谁"。**

规则：
- 连续作业正确率下降 → 提示观察学习状态
- 习惯维度骤变 → 提示观察情绪
- 家庭沟通超期 → 提示联系家长
- 收费逾期 → 提示确认续费意向

### 5.3 成长计划驱动

**v1 的成长目标是静态的。v2 的成长计划是活的。**

```
成长计划生命周期：
设定目标 → 分解为每日可执行动作 → 系统追踪执行情况 
→ 自动评估进度 → 达标/未达标触发下一步
```

## 6. 角色视角重设计

### 6.1 教师（最核心用户）

```
教师的一天：
08:30  打开 Today → 看到 3 份待复核作业、2 条观察提示
08:35  复核作业（AI 已分析，教师确认+补充）
08:45  记录 2 个孩子的习惯观察（系统已预填维度评分建议）
08:50  完成，系统自动更新成长档案
```

**v1：教师需要打开 Homework → Submissions → Review → 再切换到 Growth → Observations**
**v2：一个页面，15 分钟，全部完成**

### 6.2 校长/负责人

```
打开系统看到：
├── 本周成长交付率（多少孩子收到了有据可循的反馈）
├── 教师工作负载（复核量、观察量、沟通量）
├── 预警热力图（哪些孩子需要关注）
├── 收费健康度（合同续签、欠费情况）
└── 趋势对比（本学期 vs 上学期）
```

### 6.3 财务

```
运营 → 收费中心
├── 合同管理
├── 账单生成与追踪
├── 收款/退费记录
├── 续费提醒（关联孩子成长状态）
└── 欠费预警
```

## 7. 非功能要求

| 类别 | 要求 |
|------|------|
| 性能 | Today 页面加载 < 2s，API 响应 < 500ms |
| 可靠性 | 周报生成不丢数据，支持重新生成 |
| 安全 | JWT + RBAC，教师只能看自己的学生 |
| 可迁移 | Excel 导入幂等，支持多批次 |
| 可观测 | 核心操作审计日志，API TraceId |
| 移动适配 | Today 页面必须移动端可用（教师可能用手机） |

## 8. MVP 边界（v2 重新定义）

### v2 MVP 必须有

| 功能 | 说明 |
|------|------|
| Today 工作台 | 教师每日入口 |
| 孩子成长档案 | 学业+习惯+关联分析 |
| 作业复核流程 | AI 草稿 + 教师确认 |
| 习惯观察 | 维度评分 + 智能提示 |
| 成长计划（Lite） | 目标 + 备注 + 进度，不做复杂动作编排 |
| 周报引擎 | 自动生成 → 审阅 → 推送 |
| 收费闭环 | 合同→账单→收款→退费 |
| 机构设置 | 基础配置 |

### v2 MVP 暂不做

| 功能 | 原因 |
|------|------|
| 家长端 App | 先用周报链接代替 |
| 排课系统 | 复杂度高、与成长主线弱相关 |
| BI 大屏 | 等数据积累后再做 |
| 消息推送（微信/短信）| 先用系统内通知 |
| 多校区复杂权限 | 先做单校区 |
| AI 自动编排 | 先做 AI 辅助，不做 AI 决策 |

## 9. 成功指标

| 指标 | 目标 | 衡量方式 |
|------|------|---------|
| 有效反馈覆盖率 | ≥ 90% 学生每周收到 1 条有效反馈 | 已收到有效反馈学生数 / 在读学生数 |
| 反馈审阅率 | ≥ 95% 自动草稿被教师审阅 | 已审阅反馈数 / 自动生成草稿数 |
| 反馈按时率 | ≥ 85% 周四前完成发送 | 周四前发送反馈数 / 应发送反馈数 |
| 教师日操作时间 | 常规日 80% 情况 ≤ 15 分钟；高峰日 ≤ 25 分钟 | 操作日志时间差 |
| 作业复核时效 | 当日作业次日 12 点前复核 | 复核时间戳 |
| 预警响应率 | ≥ 80% 预警 48 小时内被处理 | 预警状态变更 |
| 收费闭环率 | 100% 合同有账单，100% 账单有状态 | 数据完整性 |
| 数据录入效率 | 比现有 Excel 流程节省 50% 时间 | 用户反馈 |

## 10. 设计原则总结

1. **成长是唯一主线** — 所有功能围绕"帮助孩子成长"组织
2. **教师是核心用户** — 系统服务教师，不是管理教师
3. **AI 是草稿不是决策** — AI 降低工作量，教师做最终判断
4. **一次录入多次复用** — 作业分析 → 错因 → 观察 → 周报 → 家长沟通
5. **看见关联而不是看见数据** — 系统发现维度间的关联，不是堆砌数字
6. **运营是基座不是中心** — 收费/考勤在后台支撑，不抢主线
7. **渐进式价值交付** — 每个版本都让用户感受到实际价值
