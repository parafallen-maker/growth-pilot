> 对应任务：`T-META-1`
> 目标：横向校核 `students / families / teachers / homework / growth / billing / jobs` 的字段命名、状态机、页面需求与契约是否一致。

---

## 1. 总结

主梁没有歪，但边角确实开始自由生长。

本次校核结论：
- 主领域对象命名基本稳定
- 关键异步字段口径已统一为 `jobId`
- 主要漂移集中在：
  1. 页面要求的聚合字段未在列表契约里具名化
  2. 页面动作已出现，但接口契约未全量跟进
  3. 个别表已存在，但接口层缺席

---

## 2. 六大域 + jobs 校核结果

## 2.1 students

### 已一致
- `student / enrollment / family` 主命名稳定
- 学生 360 已有独立聚合接口，不再要求前端手拼

### 漂移点
- 学生列表页需要的聚合列尚未在列表契约内具名化：
  - 当前老师
  - 最近作业正确率
  - 本周成长观察
  - 未收余额
- `tags` 当前仍偏 `string[]` 视角，与 `student_tags` 结构化模型存在语义落差

### 建议
- 列表与 360 分开建 schema，别把所有聚合硬塞进 `Student`
- `tags` 在接口层明确为轻量 VO，而非等同 DDL 结构

---

## 2.2 families

### 已一致
- `family / guardian` 主命名稳定
- 家庭详情聚合已预留学生、账务、任务、沟通摘要位

### 漂移点
- 页面支持 `campus / 是否有未收余额 / 是否有待办任务` 等筛选，但契约没说明这是聚合筛选
- `family_meetings` 有表无接口

### 建议
- 家庭列表筛选需要区分“基础字段筛选”和“聚合结果筛选”
- `family_meetings` 若保留，应补接口；若首发不做，文档写明后置

---

## 2.3 teachers
n
### 已一致
- 教师基础档案字段稳定

### 漂移点
- 页面需要：
  - 在带学生数
  - 待复核作业数
  - 本周观察覆盖率
- 这些还未进入教师列表/详情契约
- 页面有“新增班次”动作，契约没写接口

### 建议
- 教师详情拆基础档案与 dashboard summary 两层
- 班次类动作若非首发，页面应标注占位而非假装已有

---

## 2.4 homework

### 已一致
- `submission -> analyze -> review` 主链路命名稳定
- 分析任务返回统一 `jobId / status`

### 漂移点
- 页面有“保存草稿”，DDL / OpenAPI 尚未定义复核草稿接口或状态
- 页面提到“批量触发分析”，当前契约只有单条 analyze

### 建议
- 若保留草稿，需补 `draft` 状态或草稿存储接口
- 批量 analyze 若非本波必须，先降级为后续项

---

## 2.5 growth

### 已一致
- `rubric / observation / goal / report` 主命名稳定
- growth 页面骨架已按这四层落地

### 漂移点
- 页面存在 `reportPublished` 筛选和“是否纳入报告”概念，但 DDL/契约未完整定义
- 报告当前仅有 `generate`，缺 `review/publish` 动作接口
- `praise_records` 有表无接口

### 建议
- 报告链路至少拆 `draft / reviewed / published`
- `reportPublished` 若保留，需补明确字段或派生口径
- `praise_records` 先后置或补协议，二选一

---

## 2.6 billing

### 已一致
- `product / contract / invoice / payment / refund / renewal` 主命名稳定
- 金额口径基本统一为接口 `cents`、前端展示 `元`

### 漂移点
- 页面有“调整项”tab，DDL 有 `billing_adjustments`，契约尚未补接口
- 合同筛选比当前 OpenAPI 更丰富（如 teacher/endDateRange）

### 建议
- `billing_adjustments` 若要上页面，必须补接口
- 合同筛选统一纳入 query DTO，别让页面先猜

---

## 2.7 jobs

### 已一致
- 关键状态机口径统一为：
  - `queued / running / success / failed / canceled`
- `jobId` 口径统一

### 漂移点
- 页面已有任务中心语义，但契约只有 `GET /jobs/{jobId}`，缺 jobs 列表接口

### 建议
- 后续补 `/jobs` 列表，支持 `jobType / status / bizType / bizId` 筛选
