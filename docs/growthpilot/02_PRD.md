# 02 PRD

## 1. 产品定义

### 产品名称
洪基托管成长中心后台管理系统

### 产品定位
一套面向课后托管补习机构的 **学生成长中台 + 运营后台**。

### 核心价值
- 对学生：形成跨学期连续成长档案
- 对家长：得到可执行的反馈、任务和报告
- 对教师：降低记录成本，提高复盘质量
- 对负责人：同时看清教学、成长、出勤、收费

## 2. 用户角色

| 角色 | 主要目标 |
|---|---|
| 校长/负责人 | 看经营与教学全局，配置组织和模板 |
| 成长导师 | 维护学生档案、家庭任务、成长观察、报告 |
| 学科教师 | 上传作业、复核 AI、给出反馈 |
| 家校服务 | 维护家庭档案、沟通记录、会谈 |
| 财务 | 产品、合同、账单、收款、退款 |
| 行政/值班 | 签到、设备绑定、异常登记 |

## 3. 业务目标

### 3.1 第一优先级
1. 一人一档
2. 作业 AI + 教师复核闭环
3. 成长观察 + 周/月报告闭环
4. 家庭协同 + 收费闭环

### 3.2 第二优先级
1. 设备签到与作业时长
2. 校长总览与专项看板
3. 教师发展记录

## 4. 成功指标

| 指标 | 目标 |
|---|---|
| 学生主档覆盖率 | 100% 在读学生有主档 |
| 家庭绑定率 | >= 95% |
| 作业复核时效 | >= 90% 在 24 小时内完成 |
| 周报发布率 | >= 95% |
| 成长观察覆盖率 | 每周 >= 90% |
| 账单准时发出率 | 100% |
| 当日收款核销及时率 | >= 95% |
| 签到完整率 | >= 98% |

## 5. 产品范围

## 5.1 M01 组织与权限
**目标**：让系统从一开始就是可配置的，不靠硬编码角色。

### 功能
- 用户、角色、权限
- 校区与学期
- 数据字典
- 消息模板
- AI 任务中心

### 验收
- 能配置角色到菜单和接口级别
- 同一角色可按校区隔离数据
- 字典修改不需要改代码

## 5.2 M02 学生主数据
**目标**：从“学期表”升级为“主档 + 在读档”。

### 功能
- 学生主档
- 学期在读档
- 标签体系
- 导入与归档
- 学生 360

### 验收
- 同一学生跨学期只有一个主档
- 在 360 页面能看到作业、成长、收费、沟通摘要

## 5.3 M03 家庭管理
**目标**：把家长从通讯录变成协同对象。

### 功能
- 家庭档案
- 监护人管理
- 沟通记录
- 家长会谈
- 家庭任务

### 验收
- 一个家庭可绑定多个孩子、多个监护人
- 家校沟通形成统一时间线
- 家庭任务可跟踪完成状态

## 5.4 M04 教师管理
**目标**：支持教师工作量、带班、成长记录。

### 功能
- 教师档案
- 教师学科能力
- 班次/值班
- 教师发展记录（培训/督导/改进行动）

### 验收
- 可查看老师当前带学生数、待复核作业数、近期发展记录

## 5.5 M05 作业诊断中心
**目标**：把现有 Excel 最强链路产品化。

### 功能
- 作业提交
- AI 诊断任务
- 教师复核
- 错因词典
- 家长反馈草稿

### 验收
- 支持图片批量上传
- AI 输出结构化 JSON
- 教师可批量复核
- 最终结论可回写学生趋势

## 5.6 M06 成长管理
**目标**：把“学习习惯评分表”升级为长期成长系统。

### 功能
- Rubric 模板
- 成长观察
- 成长目标
- 表扬记录
- 周报/月报
- 家庭任务联动

### 验收
- 能按维度记录分数和文字观察
- 能按周/月生成报告草稿
- 目标和家庭任务可关联作业/观察来源

## 5.7 M07 出勤与作业时长
**目标**：沉淀到校和学习投入时长。

### 功能
- 设备管理
- 设备绑定
- 签到事件
- 作业时长会话
- 每日时长聚合

### 验收
- 设备和学生一对多绑定历史可追踪
- 可查看某学生某日总作业时长
- 当日未签到/异常时长可被检索

## 5.8 M08 收费管理
**目标**：形成可回放的收费闭环。

### 功能
- 产品与套餐
- 合同
- 账单
- 支付
- 退款
- 调整项
- 续费跟进

### 验收
- 合同、账单、支付、退款相互可追踪
- 家庭当前余额可计算
- 续费任务有负责人与状态

## 5.9 M09 沟通与消息
**目标**：统一家校消息出口。

### 功能
- 沟通记录
- 消息模板
- 消息发送任务
- 送达状态
- 报告发布联动

### 验收
- 周报、账单、家庭任务都可统一走消息中心
- 消息状态可见：草稿/待发/已发/失败/已读

## 5.10 M10 看板分析
**目标**：给负责人一个能直接决策的总览层。

### 功能
- 校区总览
- 教学质量
- 成长完成度
- 出勤异常
- 收费看板

### 验收
- 能按校区、学期、老师、年级筛选
- 核心图表来自统一统计口径

## 6. 全局业务规则

1. `student` 是核心主对象，所有业务最终都要能回到 student_id。
2. `student_enrollment` 是学期/校区/老师挂载点，不再复制学生基本信息。
3. 作业 AI 结果不能直接成为正式结论，必须经过 `homework_review`。
4. 成长观察必须关联模板与维度，不允许纯自由文本成为主记录。
5. 家长可见内容优先展示“建议、任务、进展”，而不是底层原始数据。
6. 支付与退款必须可追踪原账单或原支付。
7. 签到与时长原始事件不覆盖，只允许追加和修正标记。
8. 所有列表都支持筛选、排序、分页、导出。

## 7. 非目标

- 不做诊疗、测评、筛查类心理系统
- 不做复杂教务排课
- 不做家长自助支付网关聚合
- 不做课消与总账会计

## 8. 教育设计原则映射

| 原则 | 对应模块 | 系统落地方式 |
|---|---|---|
| 形成性评价 | homework, growth | 作业反馈、观察记录、目标跟进 |
| 正向支持与明确期望 | growth | Rubric、表扬、任务、小步目标 |
| 家校共育 | families, communication, growth | 家庭任务、会谈、周报 |
| 结构化反馈 | homework, reports | AI 草稿 + 教师复核 + 面向家长改写 |
| 高频小步追踪 | growth, attendance | 每周观察、时长、目标 check-in |

## 9. 发布计划

### Phase 1
- 组织权限
- 学生/家庭/教师
- 作业 AI + 教师复核
- 基础成长观察
- 合同/账单/支付

### Phase 2
- 周报/月报
- 出勤/设备/时长
- 沟通中心
- 数据看板

### Phase 3
- 续费自动跟进
- 更细的教师发展记录
- 更完整的 BI 快照与指标预警
