## 8. 回滚方案

### 8.1 应用回滚
1. [ ] 停止新版本 API / Web 流量
2. [ ] 切回上一稳定 commit / 镜像
3. [ ] 清理新版本缓存、队列、临时任务
4. [ ] 重新执行健康检查

### 8.2 数据回滚
> 原则：先止血，后修数。不要边冒烟边找灭火器。

1. [ ] 判断是否只涉及 staging 表
2. [ ] 判断是否需要数据库 point-in-time restore / 手动修复脚本
3. [ ] 若只涉及 staging：
   - 删除本次 `batch_id` 对应的 staging 数据
   - 保留 artifact 与 reject CSV
4. [ ] 若已触达正式表：
   - 使用发布前数据库备份恢复
   - 回放必须保留的业务增量（若有明确方案）
   - 校验 payment / refund / report / homework 关键链路
5. [ ] 如附件受影响，恢复对象存储快照

### 8.3 staging-only 回滚 SQL 模板

```sql
begin;
delete from qa_staging.staging_rejects where batch_id = '<BATCH_ID>';
delete from qa_staging.staging_normalized_rows where batch_id = '<BATCH_ID>';
delete from qa_staging.staging_raw_rows where batch_id = '<BATCH_ID>';
delete from qa_staging.import_batches where batch_id = '<BATCH_ID>';
commit;
```
