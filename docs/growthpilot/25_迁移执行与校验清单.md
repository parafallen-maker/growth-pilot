## 1. 迁移总策略

迁移统一走三层，不允许源数据直接打进正式表。

### 1.1 Layer-1：raw staging

用途：**原样落地**，先保真，再谈清洗。

建议表前缀：`staging_raw_*`

必带字段：
- `batch_id`
- `source_system`
- `source_file`
- `source_sheet`
- `source_row_no`
- `source_pk`
- `source_hash`
- `raw_payload jsonb`
- `import_status = raw`
- `created_at`

原则：
- 字段名可接近源表，不强行改业务名
- 不做业务外键
- 不在 raw 层删行
- 原始脏值也保留，后续 reject 由 normalized 层产出

### 1.2 Layer-2：normalized staging

用途：**做标准化、清洗、映射、预校验**。

建议表前缀：`staging_norm_*`

必带字段：
- `batch_id`
- `source_row_ref`
- `normalized_payload jsonb`
- `mapping_snapshot jsonb`
- `import_status = normalized | rejected | ready_to_load`
- `reject_code`
- `reject_reason`
- `created_at`

本层处理内容：
- Excel serial -> ISO date
- 百分号 -> numeric
- 学科 / 错因 / 家庭结构字典映射
- 手机号标准化
- 编号清洗与补位
- 老师 / 学生 / 家庭候选归并
- 生成稳定 `business_key`

### 1.3 Layer-3：final load

用途：**按依赖顺序写正式表**。

导入顺序以 `13_历史表迁移映射.md` + `20_DDL与迁移校核报告.md` 为准，首波重点：
1. teachers
2. families
3. students
4. student_enrollments
5. student_external_courses
6. devices
7. student_device_bindings
8. homework_submissions
9. homework_submission_files
10. homework_ai_analyses
11. homework_reviews
12. growth_observations
13. growth_observation_scores

规则：
- final load 只能吃 `ready_to_load` 数据
- 主数据先建映射表，再写事实表
- 可重算的派生表不优先迁：`homework_time_daily_stats`、`kpi_daily_snapshots`
- 迁移落库必须记录 old->new 主键映射

## 2. 首波迁移资产

本轮交付：
- `scripts/migration/run-staging-import.mjs`
- `scripts/migration/templates/reject-report-template.csv`
- 本文档（执行与校验清单）

当前脚本能力：
- 接收 `batchId`、`sourceSystem`、`sourceFile`
- 读取 `--csv` / `--json` / `--input`，默认保留 mock fallback
- 构造 raw / normalized / final load 三层 plan
- 内建字典标准化规则（学科、错因、家庭结构）
- 产出四类 reject 校验：
  - 编号冲突
  - 外键缺失
  - 字典映射失败
  - 金额链路不平
- 支持 `--dry-run`
- 支持 `--artifacts-dir <dir>` 输出：
  - `*.summary.json`
  - `*.raw.ndjson`
  - `*.normalized.ndjson`
  - `*.reject-report.csv`
  - `*.db-plan.sql`
- 支持 `--db-apply` + `DATABASE_URL` / `--db-url` 将结果 upsert 到 PostgreSQL staging 表：
  - `qa_staging.import_batches`
  - `qa_staging.staging_raw_rows`
  - `qa_staging.staging_normalized_rows`
  - `qa_staging.staging_rejects`
- staging upsert 幂等键固定为 `batch_id + source_file + source_sheet + source_row_no`

当前仍不做：
- 不直接消费原生 `.xlsx`
- 不直接 upsert 正式业务表
- 不直接完成 old->new 主键映射写回

一句话：**现在不只是有 dry-run，而是已经有了可落 staging、可出 artifact、可做幂等回放的导入入口。**

## 2.1 推荐命令

样本 dry-run：

```bash
node scripts/migration/run-staging-import.mjs \
  --dry-run \
  --csv fixtures/staging-import-sample.csv \
  --batchId BATCH-QA-DOC \
  --artifacts-dir docs/growthpilot/artifacts/2026-03-25
```

真实 DB staging apply：

```bash
DATABASE_URL=postgresql://gp:gp_dev@localhost:5432/growthpilot \
node scripts/migration/run-staging-import.mjs \
  --db-apply \
  --csv fixtures/staging-import-sample.csv \
  --batchId BATCH-PREPROD-IMPORT-001 \
  --artifacts-dir docs/growthpilot/artifacts/preprod-import
```

说明：
- `--db-apply` 只会写 staging 表，不会触碰正式业务表
- 未提供 `DATABASE_URL` 时脚本会明确失败，不会静默降级
- 本轮 QA 已验证 sample / mock 两类 artifact 输出与 reject report 模板可执行

## 4. 关键清洗规则

## 4.1 学生去重
优先级：
1. `student_no`
2. `name + grade_label`
3. `name + primary_teacher_name + term`

冲突动作：
- 若同一 `student_no` 对应多个不同姓名/年级，直接 reject
- 若无 `student_no`，但姓名+年级重复，进入人工确认池

## 4.2 老师映射
首波以姓名映射：
- 胡忠芸
- 肖顺英
- 田仙雨

若老师名不存在于教师种子 / 主数据表：
- 记 `FK_TEACHER_MISSING`
- 暂不落 enrollment/homework/growth 的 teacher 外键

## 4.3 字典映射
### 学科
- 数学 -> `math`
- 语文 -> `chinese`
- 英语 -> `english`

### 家庭结构
- 是 -> `single_parent`
- 否 -> `nuclear_or_other`

### 标准错因
- 概念混淆 -> `CONCEPT_CONFUSION`
- 方法未掌握 -> `METHOD_NOT_MASTERED`
- 计算失误 -> `CALCULATION_ERROR`
- 审题偏差 -> `MISREAD_QUESTION`
- 知识混淆 -> `KNOWLEDGE_CONFUSION`
- 遗漏作答 -> `MISSING_ANSWER`
- 表述不清 -> `UNCLEAR_EXPRESSION`
- 步骤缺失 -> `MISSING_STEPS`
- 非知识性错误 -> `NON_KNOWLEDGE_ERROR`
- 无 / 无知识性错误 -> `NO_ERROR`

## 4.4 日期与百分比
- Excel serial：转 ISO `YYYY-MM-DD`
- `85%` -> `85.00`
- 空字符串 -> `null`

## 4.5 金额
正式表统一 `cents`。

如果历史数据存在元单位金额：
- `88.5` 元 -> `8850` cents
- 禁止小数分以下精度直接截断，需 reject 或显式 round 策略

## 5. 四类核心校验口径

## 5.1 编号冲突
适用对象：
- `students.student_no`
- `teachers.employee_no`
- `contracts.contract_no`
- `invoices.invoice_no`
- `payments.payment_no`
- `refunds.refund_no`

判定：
- 同一个业务编号，对应多个不同业务主体
- 或命中 DDL 全局唯一约束但语义不一致

输出：
- `CONFLICT_STUDENT_NO`
- `CONFLICT_EMPLOYEE_NO`
- `CONFLICT_CONTRACT_NO`
- `CONFLICT_INVOICE_NO`
- `CONFLICT_PAYMENT_NO`

处理：
- raw 保留
- normalized reject
- 进入人工重编或 old->new 编号映射表

## 5.2 外键缺失
适用对象：
- enrollment -> student / campus / term / teacher
- homework_submission -> student / teacher / term
- homework_review_error_item -> review / taxonomy
- contract / invoice / payment -> family / student / invoice
- device_binding -> student / device

判定：
- 引用目标在正式表 / 映射表 / 本批主数据候选中不存在

输出：
- `FK_STUDENT_MISSING`
- `FK_FAMILY_MISSING`
- `FK_TEACHER_MISSING`
- `FK_TERM_MISSING`
- `FK_DEVICE_MISSING`
- `FK_INVOICE_MISSING`

处理：
- 不允许硬写孤儿数据
- 主数据批次需先补，再回放事实批次

## 5.3 字典映射失败
适用对象：
- 学科
- 错因
- 家庭结构
- 付款渠道
- 沟通渠道

判定：
- 源值非空，但映射表不存在

输出：
- `DICT_SUBJECT_UNMAPPED`
- `DICT_ERROR_TAXONOMY_UNMAPPED`
- `DICT_FAMILY_STRUCTURE_UNMAPPED`
- `DICT_PAYMENT_CHANNEL_UNMAPPED`

处理：
- reject
- 在映射字典补齐后重放

## 5.4 金额链路不平
适用对象：
- contracts / contract_items
- invoices / invoice_items
- payments / refunds / invoice status

判定：
1. `contract.payable_amount_cents != total_amount_cents - discount_amount_cents`
2. `sum(contract_items.subtotal_cents) != contract.total_amount_cents`
3. `sum(invoice_items.amount_cents) != invoice.amount_cents`
4. `sum(success payments) - sum(success refunds) < 0`
5. 退款金额超过支付金额

输出：
- `BALANCE_CONTRACT_PAYABLE_MISMATCH`
- `BALANCE_CONTRACT_ITEMS_MISMATCH`
- `BALANCE_INVOICE_ITEMS_MISMATCH`
- `BALANCE_REFUND_EXCEEDS_PAYMENT`
- `BALANCE_AR_NEGATIVE`

处理：
- 财务链路不做自动修正
- 一律 reject + 报告

## 6. 批次执行步骤

### 6.1 批次初始化
- 生成 `batch_id`
- 记录源文件 / sheet / 导入人 / 导入时间
- 固定本批字典版本与映射版本

### 6.2 raw load
- 原样入 `staging_raw_*`
- 保留每行 `source_row_no`
- 计算 `source_hash`

### 6.3 normalized
- 标准化字段
- 生成业务键
- 产出 reject 列表
- 标记 `ready_to_load`

### 6.4 final load
- 先主数据、后事实表
- 使用 old->new 映射表写 FK
- 每一阶段产出 load summary

### 6.5 post-check
- 行数对账
- 孤儿外键检查
- 唯一性冲突检查
- 金额平衡检查
- 随机 spot-check

## 7. 批次后校验清单

### 7.1 行数校验
- [ ] students 数 >= 历史学生去重后人数
- [ ] homework_submissions = 两张作业表总有效行数
- [ ] homework_ai_analyses = 作业提交数
- [ ] growth_observations = 习惯评分有效行数

### 7.2 约束校验
- [ ] 无孤儿 enrollment.student_id
- [ ] 无孤儿 submission.student_id
- [ ] 无孤儿 contract.family_id / student_id
- [ ] 无重复 payment_no / refund_no
- [ ] 无 active device 双绑

### 7.3 质量校验
- [ ] 日期全部为 ISO date
- [ ] 百分比全部为 numeric
- [ ] 科目全部标准化
- [ ] 错因映射结果可落 taxonomy code
- [ ] 金额统一 cents

### 7.4 业务抽样校验
- [ ] 抽 5 个学生：主档 / 在读档 / 家庭关联一致
- [ ] 抽 5 条作业：submission / ai / review 链路完整
- [ ] 抽 3 条习惯评分：observation / scores 拆分正确
- [ ] 抽 3 条设备绑定：student_no -> serial_no -> binding 一致
- [ ] 抽 3 条财务记录：金额链路平衡
