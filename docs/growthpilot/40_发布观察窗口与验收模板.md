# 40 发布观察窗口与验收模板

> 覆盖范围：`QA-30` ~ `QA-33`
>
> 用途：给上线指挥、QA、PM 一套固定模板，避免发布当天临时拼文档。

---

## 1. 使用顺序

1. 发布前填 `release-gate.yaml`
2. 发布中填 `go-live-observation.md`
3. T+24h / T+72h 继续补 observation
4. 稳定后输出 `release-acceptance-report.md`

模板位置：
- `docs/growthpilot/templates/qa_release_gate_template.yaml`
- `docs/growthpilot/templates/go_live_observation_log_template.md`
- `docs/growthpilot/templates/release_acceptance_report_template.md`

---

## 2. `QA-30` Go/No-Go

必须在会前填完：
- 发布 commit
- QA / PM / Owner
- 备份结果
- 回滚负责人
- 五条主流程 smoke 状态
- 条件放行说明

建议在会上实时投屏同一个 `release-gate.yaml` 文件，不再分散到聊天记录。

---

## 3. `QA-31` 上线后 24h 监控

24h 观察至少记录：
- API error rate
- API P95
- 首页加载时间
- DB 连接数
- 磁盘使用率
- 是否出现权限越权、金额异常、重复数据

如果 24h 内出现 P0/P1：
- 立即更新 defect log
- 判断是否进入回滚
- 观察记录必须写清时间线

---

## 4. `QA-32` 上线后 72h 稳定性确认

72h 稳定性确认最少回答三件事：
1. 是否存在未关闭 P0/P1
2. 备份任务是否连续成功
3. 用户反馈是否出现系统性问题

未完成 72h 观察前，不得把 `QA-32` 写成完成。

---

## 5. `QA-33` 发布验收报告

正式验收报告必须包含：
- 版本号、发布时间、发布人
- 功能范围
- 实际执行结果
- 已知限制
- 后续迭代计划
- QA / PM / Owner 签收

若只是把模板准备好，而没有真实发布数据，只能记为 `partial`。
