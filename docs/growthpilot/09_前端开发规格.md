## 3. 页面层级约束

### 3.1 页面分类
- List Page：列表型页面
- Detail Page：详情/360 页面
- Workbench Page：作业复核、报告编辑
- Config Page：模板、字典、权限

### 3.2 路由命名
- `/students`
- `/students/[studentId]`
- `/teachers/[teacherId]`
- `/homework/review/[submissionId]`

不要使用拼音路由。

## 4. 数据请求规范

### 4.1 query key
```ts
['students', filters]
['student-detail', studentId]
['homework-submissions', filters]
['growth-reports', filters]
```

### 4.2 服务层
每个模块只暴露：
- `query`
- `detail`
- `create`
- `update`
- `remove`
- `action`

示例：
```ts
studentService.list(params)
studentService.detail(id)
studentService.create(payload)
studentService.update(id, payload)
studentService.createEnrollment(id, payload)
```

### 4.3 表单提交
- 所有表单都必须走 Zod schema
- 表单 defaultValues 来自 DTO，不直接绑后端原始响应
- 提交成功后统一 toast + invalidate query

## 6. 组件规范

### 6.1 DataTable
必须支持：
- 列显隐
- 排序
- 行内操作
- 批量勾选
- 导出
- 空状态
- 行 hover

### 6.2 FilterBar
必须支持：
- 折叠高级筛选
- 重置
- 保存常用筛选（可选）
- 搜索后 URL 同步 query string

### 6.3 FormDialog / Drawer
- 所有弹窗表单都支持 `create / edit / readonly`
- 必须区分只读字段和可写字段
- 提交按钮在右下角固定

### 6.4 TimelinePanel
用于家庭沟通、操作日志、报告发布历史。

### 6.5 TrendChart
- x 轴统一支持日/周/月
- 悬浮 tooltip 显示完整数据
- 无数据时不渲染空图

## 7. 学生模块实现要求

- 学生列表使用服务端分页
- 学生 360 各 tab 独立请求，避免一次拉满
- 360 顶部摘要卡要从聚合接口读取，不在前端手算
- create/edit student 使用同一表单组件

## 8. 作业模块实现要求

### 上传页
- 支持多图上传
- 上传成功先拿 fileId，再创建 submission
- 上传中的本地状态放前端 store，不进 query cache

### 复核工作台
- 采用三栏布局
- 切换 submission 时保留未保存提示
- AI 结果展示 Markdown + structured JSON 双视图
- 错因勾选使用多选 + 备注输入

## 9. 成长模块实现要求

- Rubric 模板和观察表单使用动态 schema
- 观察表单支持按模板动态生成维度输入区
- 报告编辑器使用 Markdown 编辑器或简化富文本，不建议引入大型文档编辑器
- 报告预览和发布必须分离

## 10. 收费模块实现要求

- 金额统一前端显示为元，接口传输仍使用 cents
- 金额输入组件内部使用 decimal，不要直接 float
- 账单、支付、退款分标签页展示，但共用统一 family/student 过滤器

## 11. 权限处理

### 菜单权限
- 菜单树由前端根据权限点裁剪

### 按钮权限
- 所有危险动作都要单独校验 permission code

### 字段权限
- 对隐藏字段显示 `--`
- 不要仅靠 CSS 隐藏

## 12. 状态管理

### 用 TanStack Query 管这些
- 列表数据
- 详情数据
- 聚合数据
- 看板数据

### 用 Zustand 管这些
- UI 展开态
- 复核台临时草稿
- 上传过程临时文件
- 页面内未保存提醒

## 13. 错误处理

- 401：跳回登录
- 403：展示无权限
- 409：展示冲突提示，不可静默失败
- 422：表单级错误映射
- 500：记录 traceId，允许复制

### 单测

- 权限判断函数

### 组件测试
- DataTable

### E2E
- 登录

- 作业上传 -> AI -> 复核
- 观察 -> 报告发布
- 合同 -> 账单 -> 支付

## 15. UI 风格约束

- 后台风格：信息密度中等，不做花哨装饰
- 主要颜色：中性灰 + 主品牌色
- 强提醒：仅用于待处理/错误/逾期
- 所有图表都要支持导出图片或截图

## 16. 大模型生成代码时的约束

1. 先生成 feature module，不要先堆全局组件
2. 先出页面骨架，再出表单和表格列
3. API 类型以 OpenAPI 生成类型为准
4. 不要在页面里直接写 fetch
5. 不要在组件里硬编码字段名，统一从 module constants 管理
